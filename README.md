## Project Submission Requirements

Every team repository should contain:

- Project title and abstract
- Team members and project guide
- Problem statement and objectives
- Technologies used
- Installation and execution instructions
- Screenshots or demonstration link
- Project report and presentation, where required

## Project Repository Naming Convention

Format:

YEAR-SEMESTER-TYPE-BATCH-TEAMNUMBER

Examples:

- `2026-27-S7-MAIN-A-TEAM01`
- `2026-27-S7-MAIN-B-TEAM02`
- `2026-27-S5-MINI-C-TEAM01`

## Submission and Evaluation Workflow

1. Students develop projects in their working repositories.
2. A college-owned repository is created or updated for each team.
3. The project guide checks the code and documentation.
4. The project coordinator adds the official repository to this index.
5. Approved projects are published for juniors to explore.
6. Completed projects are retained under their original academic year.

## Publication Policy

- Keep projects private while evaluation or approval is pending.
- Publish only after the team and department approve.
- Check for passwords, API keys, personal data, and confidential information before publication.
