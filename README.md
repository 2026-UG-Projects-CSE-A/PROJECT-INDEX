## Repository Naming Convention

Format:

`YEAR-DEPT-TEAMID-PROJECTNAME`

Examples:

- `2026-CSE-A1-AegisSys`
- `2026-CSE-A2-TrustLens`
- `2026-CSE-A3-GreenNLP`

The year identifies the project year, `CSE` identifies the department, and the team ID identifies the batch and team.

## Required Repository Contents

Each project repository should contain:

- `README.md` — abstract, team members and roles, guide, technology stack, setup instructions, screenshots/demo, problem statement and outcome
- `LICENSE` — as approved by the guide
- `.gitignore` — configured before committing project code
- `/src` — source code
- `/tests` — automated tests, where applicable
- `/docs` — final report PDF, added after evaluation

## Submission and Evaluation

1. Each project team maintains its own repository in this organization.
2. Students use their individual GitHub accounts and make regular, meaningful commits.
3. Project guides review the source code and documentation of the teams they supervise.
4. Each project lead submits a contribution summary mapping GitHub usernames to their responsibilities.
5. The project coordinator maintains this directory and verifies repository links.

## Publication Policy

Repositories should remain **Private during development**.

After final evaluation, repositories may be made Public in accordance with departmental approval and the college's publication policy. Projects involving patent potential, external company collaboration, or sensitive data must follow the approved exemption process.

Before publishing a repository, check for API keys, passwords, access tokens, database credentials, personal data, confidential information, and third-party licensing restrictions.
